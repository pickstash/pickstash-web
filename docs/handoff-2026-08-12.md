## 1. 이번 세션 완료 (커밋됨)

### 048 — 서랍 "담기 ≠ 초대" 전면 재설계
서랍(폴더)에 상자를 담아도 더 이상 서랍 멤버가 자동으로 그 상자의 참여자가 되지 않는다.
- `box_folders` PK를 `(folder_id, box_id, added_by)`로 재구성 — **담은 사람별 스코프**. 같은 상자를 서랍 멤버 여러 명이 각자 담고, 각자 `shared`(공유/나만)를 독립적으로 정할 수 있다.
- 자동참여 트리거(`folder_box_added_join`·`folder_member_added_join`) 완전 폐기.
- `public.can_read_box(box_id)` 신설 — 참여자이거나 내가 멤버인 서랍에 (내가 담았거나 공유로) 담긴 상자면 읽기 허용. `boxes`·`box_participants`·`options`·`votes`·`comments`·`comment_likes` SELECT RLS가 이걸 쓰도록 확장(쓰기는 그대로 참여자 전용).
- `join_box(p_box_id)` RPC 신설 — "함께하기", **승인 없이 즉시 참여**(서랍으로 접근 가능한 경우 전용, 잠정 — 오남용 생기면 승인제로 전환 검토).
- `set_box_folder_shared` RPC 폐기(참여자 동기화가 더는 필요 없어 단순 UPDATE로 대체).
- 앱: `src/lib/api/folders.ts`(added_by 스코핑), `folder-view.tsx`/`folder-view.ts`(addedByMe 필드, 내가 담은 링크만 토글·빼기·순서편집), `box-detail.ts`/`box-detail-client.tsx`(`isParticipant` 읽기전용 모드), `option-detail.ts`/`option-detail-client.tsx`(동일).
- spec.md §3-7을 v4 모델로 갱신.

### 049 — 읽기전용 화면 4종(둘러보기·초대링크·프로필·공유서랍) 레이아웃 통합
- **둘러보기·프로필의 공개 상자**를 별도 `/p/[id]`(요약형·익명화) 대신 **진짜 `/box/[id]` + `BoxDetailClient`**로 흡수. `can_read_box`에 `visibility='public'`이면 anon 포함 누구나 읽기 허용 조건 추가.
- **⚠️ 보안 분기**: `join_box`(즉시 참여)를 아무 공개 상자에나 쓸 수 있게 되는 회귀를 막기 위해, `can_join_box_instantly`(드로어 접근 전용)를 따로 떼어 `join_box`의 게이트로 바꿈. 공개 상자 발견자는 기존 `request_to_join`(041, 승인제)만 쓸 수 있다. `box-detail-client.tsx` 하단 CTA가 `canInstantJoin`으로 "함께하기"/"함께하기 신청"을 분기.
- 미들웨어(`src/proxy.ts`) 정규식으로 `/box/[id]`·`/box/[id]/option/[optionId]` **딱 두 라우트만** 비로그인 허용(쓰기 전용 하위 라우트는 그대로 로그인 필수).
- `AppDrawer`에 `isLoggedIn` 게스트 상태 추가(로그아웃 대신 로그인 링크).
- `/p/[id]` 폐기 → `/box/[id]`로 redirect만 남김. `PublicBoxView` 컴포넌트·`getPublicBoxView`/`addBookmark`/`removeBookmark`(미사용) 삭제.
- **초대링크(`/invite/[code]`)**: 비공개 상자를 코드로만 접근하는 구조라 RLS로 못 흡수 — 스냅샷 RPC(`get_box_view_by_invite_code`)는 유지하되, 참여자 화면과 같은 카드 스타일(`ModeChip`·`PencilCircle`·`getLeaderKey` "인기" 임계값)로 다시 그리고, **`/invite/[code]/option/[optionId]`** 신설해 옵션 상세·댓글 전체를 별도 페이지로 분리(예전엔 한 페이지에 다 우겨넣고 댓글도 접힘).
- 공용 `PencilCircle`을 `src/components/pencil-circle.tsx`로 분리(box-detail-client·초대뷰어 공용).
- 사용자 요청으로 "구경 중이에요 · 읽기 전용" 배너는 제거(편집 UI가 없는 것 자체로 이미 충분히 드러남).

### ⚠️ 이 세션 중 발견·수정한 회귀 버그
048/049로 `boxes` RLS가 넓어지면서, **"내 상자만" 보여줘야 하는 목록**(정리중/정리완료/전체 창고 탭, 홈 브리핑)이 명시적 참여자 필터 없이 RLS에만 기대고 있던 게 드러났다 — 그 결과 공개 상자를 읽기전용으로 열람만 해도 "내 상자" 목록에 나타나는 버그가 생겼다. `src/lib/api/box-list.ts`·`src/lib/api/home.ts`에서 `box_participants`로 내 상자 id를 먼저 구해 `.in('id', myBoxIds)`를 명시하도록 고침. 안 쓰이던 `getMessyBoxes`/`useMessyBoxes`(같은 버그, 죽은 코드)는 삭제. **비슷한 패턴(참여자만 보여줘야 하는데 필터 없는 `.from('boxes')` 쿼리)이 더 있을 수 있으니, 새 목록성 쿼리를 추가할 때마다 "이거 참여자 필터 있나?"를 항상 의심할 것** — RLS가 넓어진 뒤로는 안전망이 아니다.

## 2. 이 세션과 동시에 진행된 다른 작업(참고, 제가 직접 작성 안 함)
같은 워킹트리에서 병행 세션이 홈/서랍 상자 카드를 `BoxSummaryCard`로 통일하는 작업을 하고 있었다(`src/components/box-summary-card.tsx`, `folder-view.tsx`의 `cards` prop, `folder/[id]/page.tsx`, 토스 `boxes-screen.tsx`/`folder-screen.tsx`). 이 커밋에 함께 포함돼 있고 빌드는 통과했지만, 세부 의도는 이 문서 작성자가 직접 겪은 맥락이 아니다 — 다음 세션에서 이상하면 그쪽 diff를 다시 살펴볼 것.

## 4. 주의사항 (이전 세션에서 이어짐, 여전히 유효)
- **마이그레이션 번호 충돌**: `045_bookmarks_unify`·`045_box_folder_private`, `046_join_request_resolve`·`046_profile_tags` 등 과거 병렬작업으로 번호가 겹친 채 남아있음. 언젠가 리넘버링 필요(급하지 않음).
- **types.ts 미갱신**: `join_requests`·`box_folders.added_by/shared`·`checkable`·이번 세션 신설 RPC(`join_box`·`can_read_box`·`can_join_box_instantly`) 전부 `(supabase.from('x' as any) as any)`·`(supabase.rpc as any)` 캐스팅 관례로 처리 중. 언젠가 `supabase gen types`로 재생성 권장(CLI 링크가 없어 수동 필요).
- **기존 lint 부채(이 세션 무관, 그대로 둠)**: `box-detail-client.tsx`·`app-drawer.tsx`의 `react-hooks/set-state-in-effect`(prop 동기화용 의도적 패턴), `src/lib/api/social.ts` 전체의 `@typescript-eslint/no-explicit-any`(disable 주석 없이 캐스팅된 기존 코드).
- `[id]`/`[code]` 대괄호 경로 git add는 `GIT_LITERAL_PATHSPECS=1` 필요할 수 있음.
- 토스는 앱 전체가 로그인 게이트(세션 없으면 `/invite`·`/folder-invite` 제외 전부 `LoginScreen`) — 그래서 이번 049의 "비로그인 공개 상자 열람"은 **웹 전용**이고 토스는 손대지 않았다(토스는 애초에 비로그인 방문자가 도달할 일이 없음).
